DELIVERED
A shared teal and neutral design with consistent bordered page headers, grouped
filters, tables, forms, responsive task boards, readable dates and phone layouts.
The assessment and privacy components are formatted for maintenance.

Compliance journey: /journey
The saved assessment pathway covers scope, obligations, applicability, risks,
controls, policy/evidence implementation, tests, corrective work, management
review, independent sign-off and the final external outcome. The first unfinished
step is linked. The selected step survives reload. Supporting workstreams link
people, training, suppliers, privacy, incidents, audits, approvals and monitoring.
The existing readiness gates remain server-enforced. Progress represents saved
records; a link alone is not evidence that a requirement has been satisfied.

Final outcomes: actual issued reports/certificates/filing acknowledgments and
pinned proof, or an explicit optional-certification rationale. Independent review
is required. Assessment changes invalidate the prior outcome. Approved review
or expiry dates create an owned calendar follow-up.

Audit room: dated auditor access, assigned requests, linked controls, due dates,
pinned evidence versions, comments, submission, independent acceptance/revision,
correction, reassignment, attachment removal and soft archival. Corrections clear
report review and reopen completed audits. Completion checks active requests and
the validity of retained evidence. Control owners see only their assigned room
requests. Room access windows do not restrict the organisation's other auditor
read permissions. Eligible request owners are checked on the server and in forms.

Evidence coverage: links name the supported requirement/control and source record,
filtered by the caller's read permissions. Versions stay pinned for audit review.

Notifications: each member controls their own preferences, including read-only
roles. In-app visibility is applied by the API. Email switches are exposed only
for implemented delivery paths. The bell leads with messages. The inbox supports
type/priority filters and source links. Reminder timing is explained. Workflow
emails use the existing shared Brevo/SMTP configuration and escape HTML content.

Roles: analytics uses an existing report permission, auditors can read suppliers
and training, prohibited write actions are hidden, role dashboards query real work,
and MSP portfolio navigation uses authenticated organisation memberships.

Dependencies: patched frontend and backend packages, compatible form validators,
explicit environment boolean defaults and safe partial-update parsing. Both npm
audit reports show zero known vulnerabilities at the time of this checkpoint.

Release review: reusable CI plus a manual workflow that runs checks and packages
source with revision/checksum information. This has not been run on GitHub.
